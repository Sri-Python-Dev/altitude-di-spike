# SP-13 — Parser comparison: Docling vs Azure Document Intelligence

**Status: Docling measured; Azure DI blocked.** No Azure Document Intelligence dev resource
credentials exist yet, so the Azure column is empty. Everything needed to fill it is built and
tested: `parse/azure_di.py` produces the same `ParsedDocument` as Docling (headings, text, table
cells with row/column, bboxes in PDF points), checked against a fake Azure result
(`tests/test_azure_di.py`); `eval/parsers.py --parser azure_di` and `eval/run.py --parser azure_di`
produce the step-2 and step-3 numbers as soon as `AZURE_DI_ENDPOINT` and `AZURE_DI_KEY` are set.

## Step 2 — parser metrics against golden spans

Documents: the 20 quotes in `data/golden/quotes-v1` (human-reviewed, Srini) and the 6 synthetic
edge-case quote PDFs, including one scanned (rasterised) PDF. 548 golden spans. Run
`parsers-docling-20261015T*`.

| Metric | Docling 2.138 | Azure DI layout |
|---|---:|---:|
| Golden spans found exactly | **548 / 548 (100%)** | not measured |
| Character error rate against golden spans | **0.000** (scanned PDF: 0.000) | not measured |
| Table cells recovered (quotes-v1) | **420 / 420** | not measured |
| Mean bbox IoU, located spans | 0.685 (see note) | not measured |
| Parse latency, median / max | **0.48 s / 5.9 s** (scanned PDF via OCR: 2.7 s) | not measured |

**IoU note.** 0.685 is not a location error. Most golden bboxes are word-level boxes around the
value only (e.g. `QT-2026-0004`), while Docling returns the whole line's element (`Quote Ref:
QT-2026-0004`), so the boxes overlap without matching. The three lowest documents (quote_012,
quote_008, quote_020: 0.52–0.54) are the ones with the most label-plus-value lines. For a fair
IoU comparison with Azure, both parsers must be measured against the same word-level golden boxes.

## Recommendation

**Use Docling on the controlled (local-only) route.** On this set it found every golden span
exactly (548/548), recovered every table cell (420/420) and parsed in 0.48 s median, with nothing
leaving the machine. Gaps to close before this is a real comparison:

1. Measure Azure DI on the same 26 documents (needs dev resource credentials).
2. Test real scans: the set has 1 synthetic scan, rendered from a clean PDF at 200 dpi.
3. Add word-level golden boxes so IoU compares like with like.
