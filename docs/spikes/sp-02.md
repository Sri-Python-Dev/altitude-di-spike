# SP-02 — Supplier quote document intelligence: result

## 1. Question and time box

Can we extract the fields the RFQ workflow needs from supplier quotes (PDF and email), with every
stored value traceable to an exact place in the document, accurately enough to build on?
Time box: 3 working days, 13–15 October 2026.

## 2. Method

- **Parser:** Docling 2.138 (local; OCR for scanned PDFs). Azure DI layout: not run, no credentials (SP-13).
- **Models:** `gpt-4.1-nano` and `gpt-4.1`, public OpenAI API, one prompt, structured output.
- **Grounding:** a value is stored only if its span is found on the page and the value can be read
  from it; otherwise it is stored empty with a reason. Flags come from a GoRules decision table.
- **Golden set:** 31 quote documents, 631 fields: 20 synthetic quotes (440 fields) **reviewed field
  by field by Srini** (0 corrections), plus 11 synthetic edge-case and demo quotes labelled by the
  generator. 2 more documents must be rejected (password-protected, corrupt).
- **Harness:** `eval/run.py` (not under version control); runs `current-20261015T111814Z` and
  `frontier-20261015T111630Z`; 23.5 s and 26.6 s for 31 documents.

## 4. Edge cases (all 5 pass in both runs)

Three quotes on three pages → 3 quotes; two quotes on one page → 2 quotes, each grounded to its own
values. Plain-text and HTML email bodies → 19/19 and 13/13 fields grounded (page 0, no bbox).
Scanned PDF → OCR, 19/19 fields grounded. Password-protected and truncated PDFs → rejected with a
typed reason, no retry. Same PDF renamed in a new email → skipped by SHA-256; new PDF re-sent under
the same Message-ID → processed. In the workflow test, a purchase order is classified `po` and not
extracted.

## 5. What surprised us

1. **The model's JSON leaked into its spans.** nano appended `},` to every span on 3 of 31
   documents, so grounding rejected 33 correct values (597/631). Trimming leaked delimiters and
   storing the document's own text restored 630/631 without accepting any invented span.
2. **The first golden set pointed at the wrong place.** 62 of 440 golden bboxes (14%) sat on the
   first matching characters, e.g. MOQ "9" inside the price "29.05". A "show me where" check would
   have shown the wrong spot.
3. **The frontier model bought nothing here.** gpt-4.1 cost 25× nano ($1.01 vs $0.04 per 100
   documents) for the same 630/631 on this clean set.

## 6. Recommendation

- **Parser:** Docling on the controlled route (548/548 golden spans exact, 420/420 table cells,
  0.48 s median parse). Revisit when Azure DI is measured.
- **Model route:** keep grounding mandatory: across both runs it rejected every value it could not
  prove (34 in the first nano run) and stored 0 wrong values. Do not
  standardise on gpt-4.1-nano: OpenAI lists it as deprecated. Evaluate its successor and a Foundry
  deployment with this harness before choosing; gpt-4.1 is the fallback at $1.01 per 100 documents.
- **Fields needing work before the bar is met:** lead time written in weeks (q16: 0 of 4 grounded,
  because "2 weeks" does not contain 14); incoterms with a named place and version (q16, 14 Oct:
  stored "DAP Dayton (Incoterms 2020)" against the answer "DAP Dayton"); stated total (new field, not yet in the golden set, so unmeasured).
- **Delete:** `tools/where.py` and `out/` (replaced by the app's evidence view); `docs/demo.md`
  (points to the run sheet); the three `eval/reports/2026-10-13-*` reports in the old format;
  `review_tool/` once the golden set no longer changes.

## Update, 27 October 2026: model route and confidence

**gpt-4.1-nano was switched off by OpenAI** (HTTP 404 `model_not_found`). Candidates, same harness
(31 documents, 631 fields):

| Model | Correct | Wrong stored | p50 / p95 per document | Cost per 100 documents |
|---|---:|---:|---:|---:|
| **gpt-5.4-mini (new default)** | 630 | 0 | 4.5 s / 6.1 s | $0.38 |
| gpt-5.4-nano | 630 | 0 | 6.7 s / 10.3 s | $0.11 |
| gpt-4.1-mini | 630 | 0 | 9.6 s / 17.0 s | $0.19 |
| gpt-4.1 (frontier) | 630 | 0 | 5.9 s / 10.6 s | $1.02 |

gpt-5.4-mini is the default: fastest, and not flagged deprecated (gpt-5.4-nano and gpt-4.1-mini may
be). One gpt-5.4-mini run put field labels into 5 values on one quote ("Incoterms: FCA"); 3 were
stored wrong because that text is on the page. Grounding now removes a field's own label from its
value; the rerun scored 630/631 with 0 wrong and is the regression baseline.

**Model confidence is now captured (631/631 fields) and measured, never used.** Across five runs it
carried no usable signal: mean confidence on right answers 0.990, on wrong answers 0.980–0.989;
all 7 wrong claims in the label run were reported at ≥ 0.9; gpt-4.1 reported 1.0 for every field.
With 1–7 errors per run the calibration figures (ECE 0.0015–0.01) cannot show that confidence
predicts mistakes. Evidence (grounding, rule flags) remains the only acceptance signal; calibration
is reported in every harness report for when a harder golden set exists.
